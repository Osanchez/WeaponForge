================================================================
 WEAPON FORGE - HOW TO MAKE CUSTOM WEAPONS WITH JSON
================================================================

Weapon Forge lets you create new starting weapons for PUNK by
writing small JSON text files. No programming needed. The DLL does
the work; the JSON files are the weapons.

----------------------------------------------------------------
 1. HOW IT WORKS
----------------------------------------------------------------

When the loadout (ship select) screen opens, Weapon Forge:

  1. Looks in the "weapons" folder that sits next to
     WeaponForge.dll (inside BepInEx\plugins\...).
  2. Reads every *.json file in it.
  3. For each file it CLONES an existing game weapon (the
     "template"), then overwrites any stats you listed in the
     file. Everything you don't mention stays exactly like the
     template.
  4. Adds the result to the loadout list as a new starting ship.

Because your weapon starts life as a clone of a real game weapon,
it automatically gets that weapon's projectile model, particles,
sounds, and behavior class. Your JSON then bends it into whatever
you want: faster, meaner, homing, exploding, chaining, etc.

YES - editing the JSON is enough. Change a number, save, restart
the game, and the weapon behaves differently. The DLL never needs
to be rebuilt for stat/physics/property changes.

IMPORTANT: files are read at game startup (and when the loadout
screen loads). Edits made while the game is running do NOT hot-
reload - restart the game (or fully quit to desktop and relaunch)
to see changes.

SAVING MID-RUN: custom weapons are registered with the game at
startup, so you can save-and-quit with one equipped and use
"Continue" later without the load hanging. (This is why weapons are
read at startup, not only on the ship-select screen.) If you ADD or
RENAME a weapon file, then load an old save that had the old weapon
equipped, that old id won't exist anymore - keep a file around (same
"name") as long as any save still uses it.

----------------------------------------------------------------
 2. QUICK START
----------------------------------------------------------------

  1. Run the game once with WeaponForge.dll installed. The
     "weapons" folder appears next to the DLL with an example
     file (ExamplePopper.json) already inside.
  2. Copy ExamplePopper.json, rename the copy (MyGun.json).
  3. Open it in Notepad. Change "name" to something unique,
     change "displayName" to what you want on the menu card.
  4. Edit stats. Save. Launch the game.
  5. Your weapon is a new entry on the loadout select screen.

If something is wrong with a file, the game does not crash - the
weapon is skipped and the reason is written to:
     <game folder>\BepInEx\LogOutput.log
Search the log for "WeaponForge".

----------------------------------------------------------------
 3. FILE STRUCTURE
----------------------------------------------------------------

{
  "name": "MyGun",                <- REQUIRED. Unique internal id.
                                     Letters/numbers, no spaces.
  "displayName": "MY GUN",        <- Name shown on the menu card.
  "description": "It shoots.",    <- Card description text.
  "template": "Module Weapon White Popper",
                                  <- REQUIRED. Which game weapon to
                                     clone. Decides base behavior,
                                     projectile model, sounds. Can be
                                     a weapon module OR a raw weapon
                                     asset incl. enemy weapons (sec 4).
  "slot": "primary",              <- Optional. Where it equips:
                                     "primary" (left click, default),
                                     "secondary" (right click), or
                                     "gadget1"/"gadget2"/"gadget3"
                                     (the 1/2/3 keys). See section 4b.
  "source": "starter",            <- Optional. Where it can appear:
                                     "starter" (new-game pick, default),
                                     "loot" (drops from crates), or
                                     "starterAndLoot" (both). See 4c.
  "lootWeight": 10,               <- Optional, loot only. Drop chance
                                     vs other crate modules (default 10).
  "shop": true,                   <- Optional. Buyable in the in-run
                                     shop. Independent of "source". 4d.
  "shopPrice": 150,               <- Optional, shop only. Cost in money
                                     (default 100).
  "shopUnlockLevel": 2,           <- Optional, shop only. Stations the
                                     player must unlock first (default
                                     1; 0 = from the first shop). 4d.
  "baseLoadout": "Starter_Popper",<- Optional. Which starting ship
                                     loadout to clone for the ship
                                     and module slots.
  "weapon": {                     <- Stat overrides for the weapon.
     ...see section 5...
  },
  "module": {                     <- Optional overrides for the
     ...see section 8...             module card (icon, color...).
  }
}

Rules of thumb:
- Anything you leave out keeps the template's value.
- Field names are not case-sensitive.
- A field name the game doesn't know logs a warning and is
  skipped (check the log if a change doesn't seem to apply).

----------------------------------------------------------------
 4. TEMPLATES - PICKING YOUR BASE WEAPON
----------------------------------------------------------------

The template decides the weapon's TYPE. There are four types, and
each type has its own extra fields (section 6).

PROJECTILE WEAPONS (bullets, machine guns, rifles, missiles):
  Module Weapon White Popper      - basic machine gun
  Module Weapon White Bolt        - rifle-style bolt
  Module Weapon White Dart        - darts / missiles
  Module Weapon White Shotgun     - spread shot
  Module Weapon White Blades      - blades
  Module Weapon White Derbis      - debris chunks
  Module Weapon White DiscGun     - discs
  Module Weapon Purple Marbles    - bouncing marbles
  Module Weapon Purple Flack      - flak burst
  Module Weapon Purple Shard      - shards
  Module Weapon Purple Rocket     - rockets
  Module Weapon Caps Rocket       - rockets (caps resource)
  Module Weapon Caps Flame        - flamethrower-ish
  Module Weapon Electron Rocket   - electric rocket
  Module Weapon Electron Zapper   - electric chain projectile
  Module Weapon Electron Toroid   - electric toroid
  Module Weapon White Worm

HITSCAN WEAPONS (instant laser beams):
  Module Weapon Caps Laser

PHYSICS WEAPONS (heavy lobbed objects with gravity/physics):
  Module Weapon Caps Loon
  Module Weapon Purple Can
  Module Weapon Purple ClusterCube
  Module Weapon Tech Dandelion    - (the "purple dandelion" - its
                                     real asset name is Tech)

MINION SPAWNERS (pet/drone weapons):

  Module Weapon Fly


ENEMY / RAW WEAPONS (advanced):
You can also use a raw weapon asset directly as the template, incl.
weapons enemies use. Examples:
  Weapon_Grunt          Weapon_Raven         Weapon_Zipper
  Weapon_Fly            Weapon_Fly_Laser     Weapon_PhantomDrone
  Weapon_Turret_Laser   Weapon_Turret_Worm   Weapon_CrossQueen
  Weapon Enemy Soldier  Weapon Enemy DroneMissile
  Weapon Enemy Queen Bomb   Weapon Enemy Turret Sniper
  Weapon Crawler Laser  Weapon FireBall      Weapon Fish
  Weapon Drone          Weapon BouncerRed
  Weapon Rocket Rookie  Weapon Rocket Soldier  Weapon SoldierPurple
Names come from the AssetRipper export (drop the ".asset"). Both
"Weapon_Name" and "Weapon Name" styles exist; use the exact name.
Most load fine; if one isn't in memory at the menu the log says so.

Enemy weapons are built to hurt the PLAYER, so on their own they'd
damage you, not enemies. Weapon Forge fixes this automatically:
"target" defaults to "enemies" (see section 4d), so an enemy weapon
you use will hit enemies and leave you alone. Set "target":"player"
if you actually want the original enemy behavior.

----------------------------------------------------------------
 4b. SLOTS - PRIMARY, SECONDARY & GADGETS
----------------------------------------------------------------

"slot" decides where the weapon equips:
  "primary"    left click (default) - replaces the ship's main gun
  "secondary"  right click
  "gadget1/2/3"  the 1, 2 and 3 keys

Weapons and gadgets are different MODULE TYPES, but you can mix them
freely - the "slot" you choose decides the final type, and Weapon
Forge converts as needed:
  - GADGET template + gadget slot  = the real gadget (its own
    behavior, e.g. Air Mine deploys mines). This is the normal way to
    make a gadget - pick one from the "Gadgets" group in the template
    list (section 4, "GADGET MODULES").
  - WEAPON template + gadget slot  = a gadget that fires that weapon
    (e.g. your custom rocket, on a key press).
  - GADGET template + weapon slot  = fires the gadget's weapon on
    left/right click instead of a key.

GADGETS fire on a key press with a cooldown, not held-down fire:
  - Cooldown  = 1 / fireRate  (higher fireRate = faster re-use)
  - Cost      = "cost" of "resourceUsed" per activation
  So set those weapon fields to tune how the gadget feels.
  - The loadout contains ONLY the weapon you make (plus the ship).
    A gadget loadout does NOT include the base loadout's popper on
    left-click - just your gadget.

GADGET MODULES you can use as a template:
  Module Active Purple AirMines    (air mines)
  Module Active Purple Surge       (surge)
  Module Active Purple Teardrop    (teardrop)
  Module Active Caps Igniter       (igniter)
  Module Active Caps Vial          (vial)
  Module Active Electron Circuit   (circuit)
  Module Active Generator Fuel     (fuel generator)

Example - use the real Air Mine gadget on key 1, buffed:
  {
    "name": "SuperMines",
    "template": "Module Active Purple AirMines",
    "slot": "gadget1",
    "weapon": { "damage": { "amount": 15, "damageType": "Purple" } }
  }

Example - turn a custom rocket into a gadget on key 1:
  {
    "name": "PocketRocket",
    "template": "Module Weapon Caps Rocket",
    "slot": "gadget1",
    "weapon": { "fireRate": 1.5, "cost": 3,
                "resourceUsed": "Resource White",
                "damage": { "amount": 20, "damageType": "White" } }
  }

----------------------------------------------------------------
 4c. SOURCE - STARTER WEAPON, LOOT DROP, OR BOTH
----------------------------------------------------------------

"source" controls where your weapon can show up:
  "starter"         only as a pick on the new-game loadout screen
                    (the default)
  "loot"            only as a drop - it appears inside the module
                    crates you smash open during a run, never on the
                    start screen
  "starterAndLoot"  both

HOW LOOT WORKS: the game's crates roll their module from a weighted
pool. A loot-enabled Forge weapon is added into those crate module
pools, so it can appear in any crate that drops modules. It does NOT
get added to resource/scrap drops or to enemy-specific drops - only
to crates that already drop modules.

"lootWeight" (default 10) is how likely your weapon is compared to
the other modules in that pool. The stock modules sit around weight
10, so 10 is "as common as a normal module", 20 is twice as likely,
5 is half as likely.

NOTE: loot and starter both still register the weapon at startup
(so saves keep working). "loot" just hides it from the start screen.
This does NOT add the weapon to the SHOP - only to smashable crate
drops. Shop injection is a separate system and isn't supported yet.

Example loot-only weapon:
  {
    "name": "RareCannon",
    "displayName": "RARE CANNON",
    "template": "Module Weapon Purple Rocket",
    "source": "loot",
    "lootWeight": 5,
    "weapon": { "damage": { "amount": 30, "damageType": "Purple" } }
  }

----------------------------------------------------------------
 4d. TARGET - WHO THE WEAPON HURTS
----------------------------------------------------------------

"target" controls whether the weapon damages enemies or the player:
  "enemies"  (default) hits enemies and leaves you unharmed
  "player"   hits the player (the original enemy-weapon behavior)

WHY THIS EXISTS: in PUNK a projectile only hits things on a matching
physics "layer", and enemy weapons put their shots on an enemy layer
that only collides with the PLAYER. So an enemy weapon used as-is
would damage you, not enemies. With "target":"enemies" Weapon Forge
re-lays the cloned projectile onto the player-projectile layer (and
sets a beam's hit mask to enemies), which makes it hit enemies AND,
because of how the layers work, automatically stops it hitting you.

Notes:
  - Normal player-weapon templates are already "enemies", so the
    default changes nothing for them.
  - Works for projectile, beam (hitscan), and physics weapons.
  - Does NOT apply to minion/pet weapons - a summoned minion has its
    own faction, which this option doesn't change.

Example - an enemy fireball that now hurts enemies:
  {
    "name": "MyFireball",
    "displayName": "FIREBALL",
    "template": "Weapon FireBall",
    "target": "enemies",
    "weapon": { "damage": { "amount": 8, "damageType": "Caps" } }
  }

----------------------------------------------------------------
 4e. SHOP - BUYING THE WEAPON IN A RUN
----------------------------------------------------------------

Set "shop": true to make the weapon purchasable in the in-run shop.
This is INDEPENDENT of "source" - a weapon can be a starter pick, a
loot drop, AND a shop item all at once (or shop-only).

  "shop": true              enable shop purchase
  "shopPrice": 100          cost in money/yellow (default 100)
  "shopUnlockLevel": 1      how many STATIONS you must unlock before it
                            can appear (default 1)

HOW PUNK'S SHOP UNLOCK WORKS (from the game's code): the shop is
gated by a STATION THRESHOLD, not pure chance. There's one counter
that is both "stations unlocked" and "shop tier". Every time you
unlock a station, the game rolls the next tier of shop items. So:
  shopUnlockLevel: 0  -> can appear in the very first shop (before any
                         station is unlocked)
  shopUnlockLevel: 1  -> after you unlock your 1st station (default)
  shopUnlockLevel: 3  -> after your 3rd station
Stock weapons live around tiers 1-5, so 1-3 feels natural.

Unlike stock weapons (which share a big weighted pool and only MIGHT
appear), a Weapon Forge shop weapon is added as its own guaranteed
entry - once you reach its tier it WILL show up (as long as you don't
already own it).

Notes:
  - A price is required internally; Weapon Forge sets one up for you
    (in money), so it never crashes the shop.
  - Each shop tier is rolled ONCE as you pass it, so if you're already
    past "shopUnlockLevel" when the file is added, it won't retro-
    appear that run - start a new run to see it.

Example - a mid-game shop weapon:
  {
    "name": "ShopBlaster",
    "displayName": "SHOP BLASTER",
    "template": "Module Weapon White Bolt",
    "shop": true,
    "shopPrice": 175,
    "shopUnlockLevel": 2,
    "weapon": { "damage": { "amount": 6 } }
  }

----------------------------------------------------------------
 4b. ELECTRIC / CHAIN-LIGHTNING WEAPONS (the White Tesla)
----------------------------------------------------------------

A hitscan/laser weapon can fire chain lightning like the White Tesla.
See ExampleWhiteTesla.json - it's the classic White Tesla as an editable
weapon (and, unlike the old standalone WhiteTeslaMod, it's save-safe).

These are TOP-LEVEL keys (not inside "weapon"):
  "dischargeOnFire": true   Makes the weapon fire a chain-lightning
                            DISCHARGE from the ship (hitscan guns don't do
                            this on their own). REQUIRED for lightning.
  "chainThroughEnemies": true  Lets the lightning hop enemy-to-enemy
                            (default true when dischargeOnFire). Adds a
                            conductor to every enemy - only happens if you
                            actually have an electric weapon.
  "buildupSeconds": 2       Telegraph time before the strike lands.
  "hideBeam": true          Hide the base laser beam so only the lightning
                            shows (the Tesla look).
  "lightningColor": "rainbow"  Recolor the lightning: a color name / #hex,
                            or "rainbow" for an RGB cycle. NOTE: the lightning
                            beam is shared, so this is global (all your
                            chain lightning), and the last electric weapon
                            loaded wins. Leave it out for the stock
                            white/blue look.
  "lightningRgbSpeed": 0.5  Rainbow only: hue cycles per second.
  "lightningRange": 20      How FAR the lightning reaches / arcs PER HOP -
                            the real "charge range". This is the one knob
                            that actually changes reach. It is NOT
                            chainLength (that's the NUMBER of hops) and NOT
                            the weapon's hitscan range (that's the hidden
                            laser beam). The game normally uses one global
                            reach for all electricity; this overrides it for
                            PLAYER lightning only (enemy electric attacks
                            keep their reach). It's shared across all your
                            chain weapons - last one loaded wins. Bigger
                            values = longer arcs but more chain math.

The actual lightning DAMAGE/reach lives in the weapon's discharge block:
  "weapon": { "discharge": { "damage": { "amount": 3,
                "damageType": "Resource White" },
              "chainLength": 6, "subSystem": "Player" } }
  - chainLength = how many enemies the arc hops.
  - subSystem MUST be "Player" for a visible player-side beam.
  - Damage is the discharge amount ticking over the strike window, so
    total damage = amount x ticks x chain - tune by feel, not 1:1.
Set the weapon's own "damage": { "amount": 0 } if you want ALL damage to
come from the lightning (like the Tesla).

----------------------------------------------------------------
 4c. ORBIT / SATELLITE WEAPONS (projectiles that circle you)
----------------------------------------------------------------

Turns a weapon's projectiles into a ring that orbits your ship. See
ExampleOrbitRing.json (based on the White Worm). Put it in a WEAPON slot
(primary/secondary). These are TOP-LEVEL keys (not inside "weapon"):

  "orbit": true             REQUIRED - makes this an orbit weapon.
  "orbitMode":              how it runs:
     "passive"  always spinning while equipped (default)
     "hold"     spins only while you hold fire (drains resource/sec if
                orbitHoldDrainPerSecond is set)
     "toggle"   tap fire to turn the ring on/off
     "fire"     tap fire to (re)summon the ring for orbitFireDuration sec
  "orbitDirection": "cw" or "ccw"   spin direction (default cw).
  "orbitRadius": 3          circle size - how far the orbs sit from you.
  "orbitSpeed": 140         spin speed in degrees/second.
  "orbitContactDamage": true  orbs damage enemies they touch (default true).
  "orbitDamageRepeatDelay": 0.3  seconds before an orb can re-hit the SAME
                            enemy (stops instant melt).
  "orbitBlockProjectiles": true  orbs destroy enemy shots they touch.
  "orbitPushForce": 0       shove enemies away on contact (0 = off). Set
                            contactDamage false + a push for a pure shield.
  "orbitPulse": 0           radius breathes in/out by this much (0 = off).
  "orbitSpinUp": 1          seconds to ramp from still to full spin.
  "orbitFling": true        tapping fire makes the orbs surge outward then
                            snap back (a burst attack).
  "orbitSuppressFire": true default true = a pure orbit (no forward shots).
                            false = ALSO fire the weapon normally.
  "orbitHitRadius": 0.6     how big each orb's contact area is.
  "orbitVisual": "Ammo_Worm"  which projectile art to use as the orbs
                            (default: the weapon's own projectile).
  DESTRUCTIBLE ORBS (optional):
  "orbitDestroyOnEnemy": true   orb is destroyed when it hits an enemy.
  "orbitDestroyOnTerrain": true orb is destroyed when it hits terrain
                            (fixes orbs phasing through walls forever).
  "orbitRegenMode":         how a destroyed orb comes back:
     "both"  timer AND on fire/toggle (default)
     "timer" only after orbitRegenTime seconds (best for passive)
     "fire"  only when you fire / re-toggle the weapon (active modes)
  "orbitRegenTime": 3       seconds to respawn a destroyed orb (timer).
  "orbitPopExplosion": true destroyed orb bursts - a small AoE hit at the
                            spot it died.
  "orbitPopRadius": 1.5     size of that burst.

  SPIRAL OUTWARD (orbs travel out instead of holding a ring):
  "orbitSpiral":            how the orbs move outward (default "off"):
     "off"    classic fixed-radius ring (the default).
     "launch" orbs spiral OUT from the ship, then detach at the outer edge
              and fly straight off toward enemies - they do NOT come back,
              then respawn from the center. A "vortex cannon".
     "sweep"  orbs spiral out to the edge and reset to the center, over and
              over - a continuous rotating-sprinkler sweep. They never leave,
              they just don't orbit back around.
     While spiraling, orbitRadius is the OUTER edge, and orbitPulse/orbitFling
     are ignored. Contact damage / destroy / regen still work as above.
  "orbitSpiralInner": 0.4   radius the spiral STARTS at (near the ship).
  "orbitSpiralTime": 0.8    seconds to spiral from inner to outer.
  "orbitSpiralLaunchSpeed": 12  fly-off speed once launched ("launch" mode).
  "orbitSpiralRange": 14    how far a launched orb travels before it recycles.
  See ExampleSpiralVortex.json.

HOW THE NUMBERS MAP (per your request):
  - projectileCount (in the "weapon" block) = the NUMBER of orbs, evenly
    spaced (4 = N/E/S/W). It's read LIVE, so +projectile modules add orbs
    and auto-respace them.
  - damage (in the "weapon" block) = damage per contact hit, read live so
    +damage modules scale it.
  - orbitRadius = circle size; orbitSpeed = rotation speed; orbitDirection
    = which way it spins.

----------------------------------------------------------------
 5. WEAPON FIELDS - ALL WEAPON TYPES
----------------------------------------------------------------

These go inside the "weapon": { } block and work on every type.

  "damage": { "amount": 3, "damageType": "Resource White" }
      Contact damage per hit and its element/resource type.
  "fireRate": 5             Shots per second.
  "warmupTime": 0.5         Seconds of holding fire before the
                            first shot (charge-up).
  "damageRepeatDelay": 0.1  HITSCAN / LASER weapons only (e.g. the Caps
                            Laser): seconds between damage ticks on a
                            target you're holding the beam on. Lower =
                            damages faster. Default 0.25 (4 ticks/sec).
                            NOTE: also gated by fireRate - the beam only
                            re-checks for damage each "shot", so keep
                            fireRate high enough to hit your intended tick
                            rate. (Projectiles use piercingData's own
                            damageRepeatDelay instead - see below.)
  "burstSize": 3            Shots per trigger pull (burst fire).
  "burstDelay": 0.08        Seconds between burst shots.
  "projectileCount": 5      Projectiles per shot (shotgun!).
  "spread": 30              Total spread angle in degrees when
                            projectileCount > 1.
  "angleVariance": 4        Random inaccuracy in degrees.
  "angleOffset": 0          Rotates the whole firing pattern.
  "knockbackForce": 2       Recoil pushing YOUR ship backward.
  "pushForce": 1            Force applied to whatever you hit.
  "resourceUsed": "Resource White"
                            Which ammo tank the weapon drains.
                            (White/stam, Caps/orange, Purple,
                             Electron...)
  "cost": 0.5               Ammo drained per shot.
  "barrelLength": 0.5       How far from the ship shots spawn.
  "explosion": {
      "radius": 2,
      "damages": [ { "amount": 4, "damageType": "Resource Caps" } ]
  }
  "discharge": {            Chain lightning burst (needs a
      "damage": { "amount": 3, "damageType": "Resource White" },
      "chainLength": 5,        trigger - see lifetimeData /
      "subSystem": "Player"    impactBehaviour "discharge": true)
  }
  "aimAssistData": { "enabled": true, "maxAngle": 15,
                     "isPredictive": true }
  "projectileColor": "#33ddff"
                            Recolor the projectile or beam. Accepts a
                            hex value ("#33ddff"), an HTML color name
                            ("cyan"), a game color ("ColorBlue"), or
                            "rainbow" for an animated RGB cycle.
                            Projectiles: tints sprites/trails/particles.
                            Hitscan: tints the beam sprite, light, and
                            impact particle.
  "rainbowSpeed": 0.5       Rainbow only: hue cycles per second (0.5 =
                            a full rainbow every 2 seconds). Default 0.5.
  "projectileScale": 1.5    Size multiplier. Projectiles: bigger shot
                            AND a matching larger hit radius. Hitscan:
                            beam thickness. Minions are only recolored,
                            never scaled (scaling breaks their AI).
  "burnTickRate": 0.1       BURN options (need a burn source - burn from
  "burnColor": "rainbow"    this weapon, or an AddBurnEffect). While the
  "burnRgbSpeed": 0.5       weapon is equipped:
  "burnColorTerrain": true    burnTickRate     ticks/sec ADDED to how fast
                                               burn ticks on ENEMIES
                                               (stacks with other burn
                                               weapons/modules; capped).
                              burnColor        recolor ENEMY burn flames -
                                               a color name / #hex, or
                                               "rainbow" for RGB cycling.
                              burnRgbSpeed     rainbow only: hue cycles/sec.
                              burnColorTerrain also recolor burning terrain
                                               (default false).
                            Your OWN burn is never sped up or recolored.
                            These cooperate with the Module Forge mod if
                            it's installed (no conflict); they also work
                            with Weapon Forge alone.

Sound fields (shootSfx, startSfx, warmupSfx, releaseSfx...) exist
but must exactly match sound ids already in the game's audio
database - wrong ids are silent, not broken. Easiest is to keep
the template's sounds.

Projectile/beam color is NOT tied to the damage resource in this
game - changing damageType recolors damage numbers/UI only, not the
shot. Use "projectileColor" to actually recolor the shot. Weapon
Forge clones the visual per-weapon, so recoloring never affects the
stock weapon you cloned from.

----------------------------------------------------------------
 6. TYPE-SPECIFIC FIELDS
----------------------------------------------------------------

PROJECTILE templates also accept:

  "projectileSpeed": 30
  "projectileSpeedVariance": 2
  "projectileRadius": 0.2      Hit size of the projectile.
  "usePhysics": false
  "collidesWithSlime": true
  "projectilePrefab": "..."    Asset name of ANOTHER weapon's
                               projectile - steal its look!
  "rangeData": { "enabled": true, "range": 10, "variance": 1,
                 "slowDown": false, "destroyWhenReached": true,
                 "spawnExplosion": false, "fireSub": false }
  "lifetimeData": { "enabled": true, "time": 3,
                    "timeVariance": 0.5, "spawnExplosion": true,
                    "fireSub": false, "discharge": false }
  "homingData": { "enabled": true,
                  "targetMode": "AutoSeekWhenShot",
                  "acceleration": 20, "torque": 200,
                  "maxSpeed": 15, "maxAngularVelocity": 400,
                  "turbulenceTorque": 0,
                  "turbulenceFrequency": 0 }
        targetMode options: FromLockOnly, AutoSeekWhenShot,
                            AutoSeekWhenNeeded
  "piercingData": { "enabled": true, "damageRepeatDelay": 0.2,
                    "knockBackRepeatDelay": 0.2 }
      Vanilla piercing is UNLIMITED (passes through every enemy). To cap
      it, use these TOP-LEVEL keys (not inside "weapon"):
        "pierceLimit": 2          enemies it pierces THROUGH before it
                                  vanishes on the next contact (that last
                                  enemy still takes the hit). Auto-enables
                                  piercing. Projectile weapons only.
        "pierceDamageFalloff": 0.2  damage lost per enemy pierced (0.2 =
                                  -20% to each successive enemy).
        "pierceExplodeOnLimit": true  explode when it hits the cap.

  PHASING (no-clip through terrain) - TOP-LEVEL keys:
    "phasing": true           the projectile/beam passes THROUGH terrain
                              but still hits enemies. Works on projectile
                              and hitscan/laser weapons.
    "phaseInfiniteRange": true  hitscan/laser only - the beam no longer
                              stops on walls so it reaches very far. (Or
                              set "weapon": { "range": N } to your own
                              value instead.)

  WAVE MOTION (make projectiles fly a curve instead of a straight line):
  There are TWO flavors -
   (1) CLEAN SINE "wave beam" (Super Metroid style) - TOP-LEVEL keys:
    "wave": true              projectile weaves a crisp, repeating S.
                              Projectile weapons only (NOT usePhysics/lobbed).
                              Collisions follow the visible curve. See
                              ExampleWaveBeam.json. NOTE: wave and wobble are
                              mutually exclusive - if both are on, wave wins
                              and the wobble is turned off automatically.
    "waveAngle": 30           how far the heading swings, in degrees (the
                              "width"/sharpness of the S).
    "waveFrequency": 2        wiggles per second (with projectileSpeed this
                              sets the wavelength).
    "waveMode":               how several projectiles wave together:
       "single" (default) each shot's S starts centered on its own timer.
       "synced"  rapid fire forms ONE continuous ribbon (shared clock).
       "helix"   alternate projectiles start 180 out of phase - the woven
                 "double helix" look (needs 2+ projectiles).
   (2) ORGANIC WOBBLE (a random Perlin wander, NOT a clean S) - this is the
       game's own built-in "movementNoiseData" (below). Two easy ways:
    "wobble": true            turns it on with sensible defaults.
    "wobbleAngle": 30         max wander in degrees.
    "wobbleFrequency": 3      how fast it wanders.
       ...or set "weapon": { "movementNoiseData": {...} } directly (below).

  "projectileBounceData": { "enabled": true }
  "movementNoiseData": { "enabled": true, "angle": 15,
                         "frequency": 6 }
      Organic Perlin wobble (see "wobble" above for the easy alias). This is
      a wandering path, not a clean S - use "wave" for a clean wave beam.
  "impactBehaviour": { "enabled": true, "spawnExplosion": true,
                       "fireSub": false, "discharge": false,
                       "safetyDistance": 1 }
  "electricityData": { "enabled": true, "isSource": true,
                       "chainLength": 6, "conductivity": 20,
                       "minConductivity": 0,
                       "emittedSystem": "Player",
                       "conductedSystem": "Player",
                       "showPreviewBeam": true,
                       "showBeamParticles": true,
                       "damageRadius": 0.75,
                       "damageRepeatDelay": 0.1,
                       "damage": { "amount": 3,
                                   "damageType": "Resource White" } }

HITSCAN templates also accept:

  "range": 12                Beam length.
  "rayWidth": 0.3            Beam thickness.
  "damageRepeatDelay": 0.25  Seconds between damage ticks while
                             the beam stays on a target.

PHYSICS templates also accept:

  "projectileSpeed": 10
  "projectileSpeedVariance": 1
  "projectilePrefab": "..."  (a physics object prefab name)

MINION SPAWNER templates also accept:

  "minionPrefab": "..."      Which unit gets spawned.
  "projectileSpeed": 5       Launch speed of the minion.
  "minionFacesShootDirection": true

----------------------------------------------------------------
 7. MIXING AND MATCHING
----------------------------------------------------------------

Because asset references are looked up by name, you can combine
parts of different weapons:

  - Popper stats with the Dart's missile model:
      "template": "Module Weapon White Popper",
      "weapon": { "projectilePrefab": "<dart projectile name>" }

  - A shotgun that fires homing pellets:
      "template": "Module Weapon White Shotgun",
      "weapon": { "homingData": { "enabled": true,
                  "targetMode": "AutoSeekWhenShot",
                  "acceleration": 15, "torque": 250 } }

  - A rifle whose shots explode AND chain lightning on impact:
      "weapon": { "impactBehaviour": { "enabled": true,
                    "spawnExplosion": true, "discharge": true },
                  "explosion": { "radius": 1.5, "damages":
                    [ { "amount": 3, "damageType": "White" } ] },
                  "discharge": { "chainLength": 4,
                    "subSystem": "Player",
                    "damage": { "amount": 2,
                                "damageType": "White" } } }

Exact prefab/asset names come from an AssetRipper export of the
game - the file names ARE the asset names (drop the .asset/.prefab
extension).

 8. THE MODULE CARD ("module" BLOCK)
----------------------------------------------------------------

Optional block that changes how the weapon's module looks in the
grid/inventory UI and what it grants when equipped:

  "module": {
    "displayName": "MY GUN MK II",   Card title (defaults to the
                                     top-level displayName)
    "description": "...",
    "level": 2,
    "icon": "HUD_GridTiles_8",       Module card icon. These are the
                                     weapon icon sprites; the builder
                                     page has a dropdown that picks one
                                     by weapon name. A few: Popper 13,
                                     Bolt 1, Dart/Rocket 29, Shotgun 7,
                                     Laser 8, Air Mine 25, Drone 19.
    "color": "ColorPurple",          Card color tint - a game
                                     ColorAsset name OR a hex value
                                     like "#7fd4ff" (a new color is
                                     created on the fly).
    "resourceGain": {                Change which resource (and how
      "resource": "Resource White",  much) equipping this weapon
      "amount": 12                   adds to your ship. Overrides
    },                               the template's bonus (e.g. the
                                     Caps Laser normally grants
                                     orange/caps capacity).
                                     NOTE: do NOT use "Resource Money"
                                     (or any shared/currency resource)
                                     here - the game manages those
                                     run-wide, so a per-weapon Money
                                     gain is ignored (it would hang
                                     loading). Money is fine as a
                                     "resourceUsed"/"damageType" though.
    "powerNodes": 6                  How many power cores can attach to
                                     the module (the "0 / N" cap in the
                                     grid). A number = fixed; or a range
                                     { "min": 4, "max": 8 } to roll
                                     randomly. Popper is normally 2-3.
  }

Game ColorAsset names:
  ColorWhite   ColorOrange   ColorPurple   ColorBlue
  ColorRed     ColorYellow   Color Tech    ColorPower

----------------------------------------------------------------
 9. RESOURCE NAMES
----------------------------------------------------------------

  Resource White      white / stamina
  Resource Caps       orange / caps
  Resource Purple     purple
  Resource Electron   electric / blue
  Resource Health     red / health
  Resource Money      yellow / money  (SHARED - see note below)
  Resource Fuel       fuel
  Resource Tech       tech

"Resource Money" is shared/currency and is NOT usable as a weapon
resource at all - not "resourceUsed" (ammo), "resourceGain", or
"damageType". Any of them hangs/breaks the game, so Weapon Forge
ignores/reverts Money and logs a warning. Use one of the others.

Shorthand works too: "damageType": "White" finds Resource White.
Resources decide BOTH what ammo you drain (resourceUsed) and what
damage color/type you deal (damageType) - they don't have to
match.

----------------------------------------------------------------
 10. TROUBLESHOOTING
----------------------------------------------------------------

Weapon doesn't appear on the loadout screen:
  - Check BepInEx\LogOutput.log for "WeaponForge" lines. A
    missing "name"/"template" or a typo'd template name is
    logged with your file's name.
  - Two files with the same "name" - only the first loads.
  - JSON syntax error (missing comma, quote). Paste the file into
    an online JSON validator.

A stat change didn't apply:
  - Restart the game fully - files are read at menu load only.
  - Check the log for a "does not match any field" warning: the
    field name may be misspelled, or it belongs to a different
    weapon type than your template.
  - A few game fields have intentionally odd spelling, e.g.
    "multiplyer" - copy names from this guide exactly.

Weapon appears but is silent / invisible projectiles:
  - You probably swapped in an sfx id or prefab name that doesn't
    exist. Remove the override to fall back to the template's.

What JSON canNOT do (yet):
  - Import brand-new art or sound files from outside the game.
    You can only reference assets that already exist in PUNK.
  - Make weapons drop in-game / appear in shops. Planned for a
    future version.
  - Invent behavior no game weapon has (e.g. a true black-hole
    gun). Stats and combinations only - new mechanics need C#.
